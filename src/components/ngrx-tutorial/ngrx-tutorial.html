How NgRx Works in Angular

1. Store (The Single Source of Truth)

The Store holds the global state of your application. Think of it as a local database for your Angular app. Components don't hold global state; they read it from the Store, ensuring a predictable flow.

2. Actions (Describing Events)

Actions express unique events that happen in your application (e.g., "User clicked Increment" or "Failed to load data"). Components dispatch Actions to the Store instead of mutating state directly.

this.store.dispatch(increment());

3. Reducers (Handling State Changes)

Reducers are pure functions that take the current state and the latest action to compute a new state. They are the only way to change the store's state.

on(increment, (state) => ({ ...state, count: state.count + 1 }))

4. Selectors (Reading Specific State)

Selectors extract specific pieces of data from the Store. They act as queries and can memoize (cache) results for performance. In modern Angular 16+, we can read them natively as Signals:

count = this.store.selectSignal(selectCount);

5. Effects (Handling Side Effects)

Effects listen for Actions and perform side operations like HTTP requests. Upon completion, they dispatch a new Action (Success or Failure) back to the Store, which a Reducer then handles. This isolates API calls from your UI components.
