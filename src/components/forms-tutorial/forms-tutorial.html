Forms Tutorial in Angular

1. Template Driven Forms

Concept: Forms where the logic, validation, and layout are heavily defined in the HTML template. Angular automatically creates the form model based on the directives mapped to HTML elements (like ngModel, required). Best for simple, straightforward forms.

Template Form Code Example

Username is required. Must be at least 3 characters long.
Email is required. Must be a valid email format.
Key Points (Template Driven):
  • ngModel: Used with two-way binding [(ngModel)]="..." to track inputs.
  • Validation: Relies on native HTML attributes (required, minlength, email). Angular provides validation directives behind them.
  • Form Reference: We export the form state using #tdForm="ngForm" to check properties like tdForm.invalid.

2. Reactive Forms (Most Important)

Concept: Forms where the explicit structure, validation rules, and logic are defined in the TypeScript component class. The template just binds to these programmable models. Best for complex layouts, dynamic structure, and easy testability.

A. Standalone FormControl

A FormControl tracks the value and validation status of an individual form control.

Key Points (Reactive Forms):
  • FormGroup: Tracks the value and validation status of a group of child FormControls.
  • FormBuilder: We inject `FormBuilder` to create controls array/groups concisely instead of calling `new FormGroup(...)`.
  • Custom Validator: Built a forbiddenNameValidator that marks "Bob" as invalid using a Regex.
  • Async Validator: Built uniqueUsernameValidator that returns an Observable, simulating an HTTP request to check "admin".
  • Cross-field validation: Applied a custom validator `identityRevealedValidator` at the FormGroup level to check interactions between siblings.
  • Dynamic Forms: Leveraged FormArray logic to push/remove alias controls dynamically with simple array methods.
